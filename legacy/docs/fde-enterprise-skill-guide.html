01

不是 Prompt 集合，
而是交付能力操作系统

仓库以可重复执行、检查和验收的能力包为基本单元。选择 Skill 的起点是项目阶段与决策问题，而不是模型、框架或厂商名称。

三层企业分类

主交付链：01–07，覆盖立项、发现、方案、构建、部署、集成和采纳。

横切门禁：08，把数据、权限、工具和生产风险变成可审计条件。

方法与资产：09–11，提供行业样例、模板、全流程总控和产品化复用。

六条使用原则

  1. 先定阶段，再选 Skill
  2. 先证据，后方案
  3. 一个主 Skill，若干辅 Skill
  4. 用 evaluation.md 结束任务
  5. PoC 成功不等于企业落地
  6. 项目结束必须资产化

04

两种核心调用形态

当前仓库已经形成一致的方法论，但自动发现形态仍处于混合状态。使用时先判断目录中是否有 SKILL.md。

Mode A · Agent Native

含 SKILL.md 的 8 个核心 Skill

Growth Roadmap、Self Assessment、Issue Tree、Sidecar、PoC Tech Stack、Full Lifecycle、Diagnostic FDE、Customer-Product Bridge。

请使用 fde-poc-tech-stack-selector Skill。
背景：……
Primary Metric：……
数据与部署约束：……
输出主方案、降级方案、淘汰项、
10 日计划和 Go/No-Go。
Mode B · Four-Part Package

README + Prompt + Checklist + Evaluation

多数核心能力采用四件套；少数另有 workflow.md。显式告诉 Agent 目录，并要求逐个读取和执行。

请按 `02-Discovery/Business-Interview/` 执行：
1. README.md 确认边界
2. prompt.md 选择本阶段 Prompt
3. checklist.md 作为过程门禁
4. evaluation.md 判断能否进入下一阶段
5. 输出证据与待确认项
Implementation Extension

19 个外部镜像 Skill

本地核心 Skill 决定业务问题、交付物与验收；外部 Skill 补充工程模式。版本、许可、数据流和安全边界仍须重新核验。

05

六套典型组合打法

组合的目的不是调用更多 Skill，而是为每个 Stage Gate 选择恰好足够的证据和交付物。

01 · New Customer PoC

从模糊需求到生产

Stakeholder → Interview → Process → Problem Solving → SOW → PRD → Tech Stack → Eval/Audit → Deploy → Integrate → Adopt → Product Bridge

用 FDE-Full-Lifecycle 做总控，各专项 Skill 负责具体交付物。

02 · Enterprise RAG

知识库效果治理

Interview → Process → Issue Tree → Tech Stack → RAG Evaluation → Deploy → Adoption

先做小规模 Golden Dataset，把解析、召回、生成、引用和业务采纳分层评估。

03 · Agent / MCP

工具型 Agent 落地

Problem Solving → PRD → API Review → Tech Stack → Tool Audit → RBAC → Deploy

确定性流程优先；高风险动作必须有最小权限、确认、幂等、审计和回滚。

04 · Private / Xinchuang

信创、内网、数据不出域

Stakeholder → Interview → RBAC 前置 → Tech Stack → Private Gateway → API Review → Integration

私有化不仅是模型落内网，还包括身份、密钥、日志、供应链、容量、灾备和运维接管。

05 · Sidecar

主链路阻力大时体外验证

Stakeholder → Process → Sidecar → AIBP → Tech Stack → Fast PoC → Adoption → Merge / Keep / Stop

Sidecar 不能绕开治理；需预先定义数据同步、审计、回退和终止条件。

06 · Adoption Rescue

PoC 成功但没人用

Adoption → Re-interview → Re-map Process → Expectation → Dashboard → Executive → Product Bridge

优先排查真实需求、使用成本、可信度、Champion、反馈入口和任务成功指标。

06

治理与仓库维护

能力包的价值来自现场证据、时效性和可复用性，而不来自目录数量。

usable ≠ validated

31 个核心 Skill 当前成熟度为 usable。项目复盘应记录客户类型、采用步骤、结果指标、失效内容和成熟度升级证据。

补齐自动发现

优先为 Interview、Process、PRD、RAG Evaluation、Tool Audit、Private Gateway、RBAC 和 Adoption 补齐 SKILL.md。

选型保持时效

涉及“最新、支持、兼容、可私有化、生产级”的判断，必须在执行当天核对官方文档、Release 和许可证。

保护企业数据

客户密钥、生产配置、个人信息和受监管数据不得进入未批准服务；高风险动作保留人工确认和审计。

07

打印与 PDF 导出

HTML 已包含 A4 打印样式；Markdown 包含 YAML 元数据、目录层级和分页标记。

推荐：浏览器直接打印本页

选择 A4、背景图形开启、页边距默认。也可以使用 Markdown 版配合 Pandoc + XeLaTeX。

cd /Users/admin/Documents/Github/fde-skills
pandoc docs/fde-enterprise-skill-guide.md \
  --from=gfm+raw_html \
  --toc --number-sections \
  --pdf-engine=xelatex \
  -V CJKmainfont="PingFang SC" \
  -V geometry:margin=20mm \
  -o docs/fde-enterprise-skill-guide.pdf
